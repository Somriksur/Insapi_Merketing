  PROBLEM 1 — Antivirus Detecting Installer as Suspicious
================================================================================

  Problem : Antivirus detecting while installing. Needs certifications so it
            does not look suspicious.

  Root Cause:
    - PyInstaller exe had no version metadata → looked like unnamed malware
    - UPX compression was on → identical signature to packed malware
    - console=True → hidden terminal process triggered heuristic AV alerts

  Fixes Applied:
    → desktop/backend.spec : upx=False
         UPX compression is the #1 cause of AV false positives.
         Disabled completely — binary is uncompressed and transparent.
    → desktop/backend.spec : console=False
         Windowed exe. No hidden terminal process spawned.
         Silent console apps are a major AV red flag. Now fixed.
    → desktop/backend.spec : version=_ver_file
         Embeds Windows PE metadata into the .exe:
           Company Name    = Insapi Marketing
           Product Name    = Insapi Marketing Workspace
           File Version    = 1.0.0.0
           Legal Copyright = Copyright 2026 Insapi Marketing
         AV scanners give more trust to attributed executables.
    → desktop/backend.spec : excludes = [tkinter, matplotlib, scipy,
         test, unittest, distutils, setuptools, pip, jupyter]
         Smaller binary = fewer heuristic hits from AV scanner engines.

  Test Results:
    ✅ PASS  upx=False confirmed in backend.spec
    ✅ PASS  console=False confirmed in backend.spec
    ✅ PASS  version=_ver_file (PE metadata) confirmed in backend.spec

  Important Note:
    The only 100% permanent fix for Windows SmartScreen "Unknown Publisher"
    warning is a paid EV Code Signing Certificate (~$300-500/yr from
    DigiCert or Sectigo). All fixes above significantly reduce AV false
    positives but the SmartScreen warning on first launch requires a cert.

  PROBLEM 2 — Installer Closes and Restarts After Giving Admin Access
================================================================================

  Problem : After approving UAC (giving admin access), installer closes and
            starts again from the license agreement screen.

  Root Cause:
    - allowElevation=false + requestedExecutionLevel=asInvoker created a
      conflict. Windows tried to re-elevate via all-users mode and restarted
      the installer in a loop.

  Fixes Applied:
    → desktop/package.json win section:
         "requestedExecutionLevel": "highestAvailable"
         (was "asInvoker" — requests elevation once cleanly at startup)
    → desktop/package.json nsis section:
         "allowElevation": true
         (was false — this was the direct cause of the restart loop)
    → desktop/installer-simple.nsh:
         StrCpy $isForceCurrentInstall "1"
         Forces current-user installation, preventing the all-users
         UAC re-launch code path entirely.

  Test Results:
    ✅ PASS  requestedExecutionLevel = "highestAvailable" in package.json
    ✅ PASS  allowElevation = true in package.json
    ✅ PASS  isForceCurrentInstall present in installer-simple.nsh

         Created at startup — 4 worker threads always ready.
    → backend/server.py invoice_pdf() endpoint:
         pdf_bytes = await asyncio.get_event_loop().run_in_executor(

         PDF generation (CPU-bound) runs in thread pool.
         Endpoint stays non-blocking — other requests not held up.
    → backend/server.py send_invoice_email():
         SMTP connection + send runs in thread pool via run_in_executor.
         Email sending (I/O-bound + slow) does not block the server.
    → backend/server.py on_shutdown():
         _executor.shutdown(wait=False) — clean thread pool teardown.
    → All API endpoints use async/await throughout — non-blocking I/O.
    → FastAPI's asyncio event loop handles all concurrent requests.

  Test Results:
